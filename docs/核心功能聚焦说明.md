# 核心功能聚焦说明

## 平台核心定位

Builder 平台的核心是：**应用部署平台**

## 核心功能域

### 1. 应用配置管理 ⭐⭐⭐
**目标**: 管理应用在不同环境的配置参数

**核心功能**:
- 多层级配置（平台 → 项目 → 环境 → 服务）
- 7级优先级覆盖
- 配置分类（环境变量、配置文件、敏感配置）
- 配置模板（快速初始化）
- 配置快照（OBOM、精确回滚）

**已完成**: ✅ 100%

### 2. 资源管理与绑定 ⭐⭐⭐
**目标**: 管理应用依赖的外部资源（数据库、缓存、消息队列）

**核心资源类型**（聚焦应用依赖）:
- **数据库**: GaussDB（实例 → Schema → User）
- **缓存**: Redis
- **消息**: Kafka、MQS
- **配置中心**: Config Center
- **集群**: CCE Cluster、Namespace（K8s基础）

**核心功能**:
- 资源CRUD（创建、查询、更新、删除）
- 资源版本管理
- 资源父子链（自动继承属性）
- 资源绑定到服务（通过别名）
- 资源导出（自动生成环境变量）
- 资源自动申请（配置驱动）

**已完成**: ✅ 90%

### 3. K8s 资源渲染 ⭐⭐⭐
**目标**: 将应用配置和资源绑定渲染成 K8s 对象

**核心 K8s 对象**:
- **Deployment**: 应用部署（副本、镜像、探针、资源限制）
- **Service**: 服务暴露（ClusterIP、NodePort）
- **Ingress**: 外部访问（域名、路径、TLS）
- **ConfigMap**: 配置文件、环境变量
- **Secret**: 敏感配置、密钥
- **HPA**: 自动扩缩容
- **PDB**: 高可用保障

**渲染流程**:
```
阶段1: 参数装配
  ├─ 服务属性（replicas、resources、ports）
  ├─ 配置参数（7级覆盖后的配置）
  └─ 资源导出（数据库连接、Redis地址）
  ↓
阶段2: 渲染 values.yaml
  ├─ 统一数据结构
  └─ 所有参数归一化
  ↓
阶段3: 渲染 K8s 对象
  ├─ Deployment（完整字段）
  ├─ Service
  ├─ Ingress
  ├─ ConfigMap/Secret（4个对象）
  └─ HPA/PDB
```

**已完成**: ✅ 100%

### 4. 部署流程 ⭐⭐⭐
**目标**: 从配置到运行应用的完整流程

**核心流程**:
```
1. 配置解析（7级优先级覆盖）
   ↓
2. 资源绑定（查询资源、展开父链、解密）
   ↓
3. 参数装配（五级覆盖）
   ↓
4. K8s 渲染（两阶段渲染）
   ↓
5. 对象应用（GET + create/update）
   ↓
6. 就绪检查（observedGeneration、replicas）
   ↓
7. 配置快照（OBOM记录）
```

**已完成**: ✅ 90%

## 不在核心范围

### 外部服务集成（仅作为配置使用）
- APIG插件 ❌（不是应用核心依赖）
- OBS存储 ❌（不是应用核心依赖）
- SWR组织 ❌（镜像仓库是基础设施）
- ACC/KMS ❌（平台级服务）

**说明**: 这些服务可以通过"通用端点"资源类型管理，不需要专门的资源类型。

### 复杂的编排
- 跨服务依赖 ❌
- 复杂的工作流 ❌
- 蓝绿部署 ❌（未来增强）

## 核心价值主张

### 对开发者
- **简化配置**: 不用关心不同环境的差异，平台自动覆盖
- **自动绑定**: 数据库、Redis等资源自动注入环境变量
- **标准化**: 统一的应用部署模型

### 对运维
- **可追溯**: 完整的配置历史和快照
- **可回滚**: 基于OBOM的精确回滚
- **高可用**: HPA自动扩缩容、PDB保障

### 对平台
- **规范化**: 7级配置优先级清晰
- **可扩展**: 两阶段渲染易于扩展
- **高性能**: 配置解析<50ms，渲染<100ms
