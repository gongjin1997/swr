# SWR Builder 平台架构分析与全面改进方案

基于 XAC 系统设计的深度分析，本文档全面审视 SWR Builder 平台的架构缺陷，并提出系统性改进方案。

---

## 一、架构对比：XAC vs Builder

### 1.1 XAC 的核心设计理念

**一次部署 = 环境 × 产品/DU × 制品版本 × 绑定资源 × 配置**

XAC 通过清晰的领域模型和分层架构，将复杂的 K8s 应用部署抽象为：

```
参数装配（5级覆盖）
  ↓
客户端初始化（注解注入）
  ↓
两阶段 Mustache 渲染（values.mustache → 各模板）
  ↓
K8s 对象提交（GET + create/update）
  ↓
状态查询与回退
```

**关键设计决策**:
1. **envId 作隔离主键** - 所有配置、资源、证书按环境归属
2. **三层配置覆盖** - 全局 > DU > 默认（按 type 优先级）
3. **资源父子链** - cce_cluster→namespace→image_secret，gauss_db→gauss_schema→gauss_user
4. **二阶段渲染** - 先渲染 values，再用 values 渲染各模板
5. **注解驱动参数注入** - @Config/@ResourceConfig 自动注入客户端配置
6. **两层调度** - 优先级队列 + 依赖记录

### 1.2 Builder 当前架构

**当前实现**:
```
服务配置（4层：平台→项目→环境→服务）
  ↓
配置解析（resolve_config）
  ↓
Jinja2 模板渲染（单阶段）
  ↓
K8s 对象生成（render）
  ↓
直接 apply（无 GET 检查）
```

## 二、Builder 平台的核心缺陷

### 2.1 配置体系缺陷

#### 问题 1: 配置层级混乱，缺少明确的优先级语义

**XAC 做法**:
- 配置分为 4 个独立维度：stage（init/app）、type（DEFAULT/DU/GLOBAL × COMMON/SECRET）、作用范围（envId + productName + duName）、processType
- 明确的优先级：GLOBAL_SECRET(7) > GLOBAL_COMMON(6) > DU_SECRET(5) > DU_COMMON(4) > DEFAULT_SECRET(3) > DEFAULT_COMMON(2) > FEATURE(1)
- 配置更新有明确的生效机制（刷新 ConfigMap 或重启 Pod）

**Builder 现状**:
- 只有简单的 4 层覆盖（平台→项目→环境→服务）
- 没有区分初始化阶段和应用阶段的配置
- 缺少"全局强制覆盖"语义（无法从环境层强制覆盖服务层配置）
- 没有配置的 processType（字符串替换、环境变量、挂载文件等）
- 配置更新后没有明确的生效路径

**影响**:
- 无法实现"某些配置必须从平台层统一下发，服务层不能覆盖"
- 配置变更后不知道如何生效（是否需要重启、是否需要完整发布）
- 无法区分"初始化配置"和"运行时配置"

#### 问题 2: ConfigMap 和 Secret 的生成逻辑不完整

**XAC 做法**:
- config_global 制品生成 2 个 ConfigMap：`production-config`（业务配置）、`properties`（框架配置）
- config_secret 制品生成 2 个 Secret：`configcenter`（配置中心敏感数据）、`certs-secret`（证书）
- 每个 ConfigMap/Secret 有明确的挂载路径和用途
- 支持配置刷新（updateConfigMap/updateSecret）

**Builder 现状**:
- 只生成一个 ConfigMap（环境变量形式）
- Secret 只用于镜像拉取凭据（imagePullSecrets）
- 配置文件需要手动挂载，没有统一的生成机制
- 不支持配置中心集成
- 缺少证书管理机制

**影响**:
- 无法优雅地处理配置文件（如 application.yml、logback.xml）
- 证书更新困难（无法从平台层统一分发）
- 敏感配置和普通配置混在一起
- 无法实现配置热更新

#### 问题 3: 资源绑定的导出不完整

**XAC 做法**:
- 资源属性通过模板占位符导出：`{{resource.gauss_db.host}}`、`{{resource.gauss_schema.schema}}`
- 支持父资源属性继承：子资源可以引用父资源属性 `{{parent.host}}`
- 资源绑定作为独立的配置层（binding scope，优先级 2.5）
- 支持资源申请配置（INIT + GLOBAL_COMMON）

**Builder 现状**:
- 资源导出只支持环境变量（`CACHE_HOST`、`CACHE_PORT`）
- 父链展开刚刚实现，但没有统一的占位符语法
- 资源绑定没有独立的配置层级
- 不支持资源申请配置（如动态创建 Schema、User）

**影响**:
- 无法在配置文件中引用资源属性（只能通过环境变量）
- 资源变更后配置无法自动更新
- 无法实现资源的自动化申请和配置

### 2.2 模板体系缺陷

#### 问题 4: 单阶段渲染，缺少参数装配阶段

**XAC 做法**:
- **两阶段渲染**：
  1. 阶段 1：渲染 `values.mustache`，生成完整的参数 YAML
  2. 阶段 2：用 values YAML 作为最高优先级作用域，渲染各个 K8s 对象模板
- 参数装配：getParams 五级覆盖（feature < resource < DU attr < 制品占位符 < cert）+ externalParams（客户端生成）
- 扁平 key 胜过嵌套 map，`{{key ? default}}` 只在 key 整个缺失时生效

**Builder 现状**:
- **单阶段渲染**：直接用配置字典渲染 Jinja2 模板
- 参数装配混在渲染过程中
- 没有明确的参数优先级规则
- 缺少参数的预处理和验证阶段

**影响**:
- 模板复杂度高，难以维护
- 参数来源不清晰，难以追踪
- 无法实现复杂的参数计算逻辑
- 模板复用困难

#### 问题 5: K8s 对象生成不完整

**XAC 生成的完整对象**:
```
image 制品 →
  - Deployment（包含健康检查、资源限制、volume 挂载）
  - Service（NodePort/ClusterIP）
  - Ingress（ELB 绑定、证书、路由规则）
  - HPA（CPU/内存指标、扩缩容行为）
  - ConfigMap（注入环境、JVM 参数）

config_global 制品 →
  - production-config ConfigMap
  - properties ConfigMap

config_secret 制品 →
  - certs-secret Secret
  - configcenter Secret
```

**Builder 当前生成**:
```
服务发布 →
  - Deployment（基本配置）
  - Service（简单端口映射）
  - Ingress（基本路由）
  
缺失：
  - HPA（没有自动扩缩容）
  - PodDisruptionBudget（没有中断预算）
  - NetworkPolicy（没有网络策略）
  - ServiceMonitor（Prometheus 监控）
  - 完整的 ConfigMap/Secret 管理
```

**影响**:
- 无法实现自动扩缩容
- 缺少高可用保障（PDB）
- 无法实现网络隔离
- 监控集成困难

#### 问题 6: 模板字段不完整

**XAC 模板字段**（部分列举）:

**Deployment**:
- `replicas`（副本数，支持 HPA 时置 null）
- `revisionHistoryLimit`（历史版本保留数）
- `strategy`（滚动更新策略：maxSurge、maxUnavailable）
- `minReadySeconds`（最小就绪时间）
- `progressDeadlineSeconds`（进度超时）
- `resources.requests/limits`（资源请求和限制）
- `livenessProbe/readinessProbe/startupProbe`（三种探针）
- `lifecycle.preStop`（优雅关闭）
- `securityContext`（安全上下文）
- `affinity/nodeSelector/tolerations`（调度）
- `volumes/volumeMounts`（卷挂载）

**Service**:
- `type`（ClusterIP/NodePort/LoadBalancer）
- `sessionAffinity`（会话亲和性）
- `externalTrafficPolicy`（外部流量策略）

**Ingress**:
- `ingressClassName`（Ingress 类）
- `annotations`（ELB 配置、证书 ID）
- `tls`（TLS 配置）
- `rules`（路由规则：host、path、pathType）

**HPA**:
- `minReplicas/maxReplicas`
- `metrics`（CPU/内存/自定义指标）
- `behavior`（扩缩容行为：稳定窗口、策略）

**Builder 当前字段**:
- Deployment: replicas、image、ports、env、resources（基本）
- Service: ports、selector
- Ingress: host、path、serviceName、servicePort

**缺失字段**:
- 没有探针配置（健康检查不完整）
- 没有滚动更新策略（无法控制发布速度）
- 没有优雅关闭配置（可能导致请求丢失）
- 没有安全上下文（无法限制容器权限）
- 没有 HPA 任何字段

### 2.3 资源管理缺陷

#### 问题 7: 资源类型系统不完整

**XAC 资源体系**:
- **明确的资源分类**：
  - 集群资源：cce_cluster、namespace、image_secret
  - 数据库资源：gauss_db、gauss_schema、gauss_user（三层父子链）
  - 中间件资源：redis、kafka、mqttbroker
  - 接入资源：ingress_elb、elb_certificate、apig_group
  - 平台资源：acc、kms、swr
- **资源绑定联动**：创建 namespace 自动创建 image_secret，创建 gauss_schema 自动绑定父 DB
- **资源申请配置**：支持通过配置（INIT + GLOBAL_COMMON）动态申请资源

**Builder 当前实现**:
- 资源类型：gauss_db、gauss_schema、gauss_user、redis、kafka、mqs、config_center、iam、endpoint（9 种）
- 父子链：只支持 3 层（db→schema→user）
- 资源绑定：手动绑定，没有联动
- 资源申请：不支持

**缺失**:
- 缺少集群资源管理（cluster、namespace 不在资源系统中）
- 缺少证书资源（elb_certificate）
- 缺少 API 网关资源（apig_group、apig_plugin）
- 缺少平台账号资源（ACC、KMS、SWR）
- 不支持资源自动申请和初始化

#### 问题 8: 资源属性定义不完整

**XAC 资源属性示例（gauss_schema）**:
```java
host: 从父资源（gauss_db）继承
port: 从父资源继承
username: 从父资源继承
password: 从父资源继承（敏感）
schema: 自身属性
```

**导出规则**:
```
GAUSS_HOST={{parent.host}}
GAUSS_PORT={{parent.port}}
GAUSS_SCHEMA={{schema}}
GAUSS_USER={{parent.username}}
GAUSS_PASSWORD={{parent.password}}
```

**Builder 当前实现**:
```python
gauss_schema:
  - schema (required)
  - parent_type: gauss_db
  
导出:
  - 通过 parent_chain 继承，但没有明确的占位符语法
  - 导出只支持环境变量，不支持模板占位符
```

**缺失**:
- 资源属性定义不够详细（缺少 username、password 等关键字段）
- 导出规则不灵活（只支持环境变量）
- 没有占位符系统（无法在配置文件中引用资源属性）

### 2.4 部署引擎缺陷

#### 问题 9: 缺少完整的部署流程

**XAC 部署流程**:
```
1. 环境上下文设置（EnvInterceptor）
2. 参数装配（getParams 五级覆盖）
3. 副作用执行（processListeners: 证书读取、资源绑定验证）
4. 客户端初始化（initClient 注解注入 kube_config）
5. 两阶段渲染（values.mustache → 各模板）
6. K8s 对象提交（GET + create/update，Deployment 加 restartedAt）
7. 状态查询（queryImageDeployStatus 轮询就绪）
8. OBOM 记录（记录实际生效的参数和对象版本）
```

**Builder 当前流程**:
```
1. 固定镜像 digest
2. 检查策略（冻结、发布窗口）
3. 创建发布记录（待审批/排队）
4. 审批（如需要）
5. Worker 执行：
   - resolve_config（配置解析）
   - render（模板渲染）
   - apply（直接提交）
6. 等待 rollout 完成
```

**缺失**:
- 没有环境上下文机制（envId 隔离）
- 没有参数装配阶段（五级覆盖）
- 没有副作用执行机制（Listener 模式）
- 没有客户端初始化配置（kube_config 硬编码）
- apply 前不检查对象是否存在（无 GET）
- 没有 OBOM 记录（不知道实际生效了什么）

#### 问题 10: 缺少依赖管理和调度

**XAC 调度机制**:
- **两层调度**：
  1. 优先级队列（DuQueueManager）：按优先级和创建时间排队
  2. 依赖记录（deploy_record_dependency）：config_global/config_secret 必须先于 image 部署
- **状态管理**：QUEUED → RUNNING → SUCCESS/FAILED/CANCELED
- **并发控制**：同一 DU 的部署任务串行执行

**Builder 当前实现**:
- **单一队列**：Celery 任务队列，按 FIFO
- **无依赖管理**：发布记录之间没有依赖关系
- **无并发控制**：同一服务可以同时有多个发布任务

**影响**:
- 无法保证配置先部署再部署应用
- 无法实现批量部署的依赖编排
- 并发发布可能导致冲突

### 2.5 状态管理缺陷

#### 问题 11: 就绪判断不完整

**XAC 就绪判断**:
```java
// Deployment 就绪条件
1. status.observedGeneration == metadata.generation（确保是最新版本）
2. status.updatedReplicas == spec.replicas（所有副本已更新）
3. status.availableReplicas == spec.replicas（所有副本可用）
4. 无 Progressing=False 条件（没有进度失败）

// Pod 就绪判断
1. phase == Running
2. 所有 container 的 ready == true
3. 所有 readinessGate 通过
```

**Builder 当前实现**:
```python
# 等待 Deployment rollout 完成
kubectl rollout status deployment/{name}

# 简单的副本数检查
available_replicas == desired_replicas
```

**缺失**:
- 没有检查 observedGeneration（可能判断到旧版本）
- 没有检查 Progressing 条件（无法感知发布失败）
- 没有检查 Pod 的详细状态（可能误判就绪）
- 没有超时和重试机制

#### 问题 12: 缺少 OBOM 记录

**XAC OBOM 记录**:
- **记录内容**：
  - 部署时使用的所有参数（配置快照）
  - 生成的 K8s 对象（YAML 完整内容）
  - 资源绑定版本（resource_id + version）
  - 证书版本
  - 执行时间、执行人、执行结果
- **用途**：
  - 审计：知道历史上每次部署的完整上下文
  - 回滚：可以精确回滚到某个历史版本
  - 对比：可以对比两次部署的差异

**Builder 当前实现**:
- **记录内容**：
  - deployment_id、service_id、revision、config_version
  - 镜像 digest
  - 状态、审批记录
- **缺失**：
  - 没有配置快照（只记录 config_version，但配置可能已变）
  - 没有 K8s 对象记录（不知道实际生成了什么）
  - 没有资源绑定快照（只记录当前绑定，但资源可能已更新）

**影响**:
- 无法精确回滚（配置和资源可能已变）
- 无法审计（不知道历史上部署了什么）
- 排查问题困难（无法对比差异）

### 2.6 可扩展性缺陷

#### 问题 13: 缺少扩展点机制

**XAC 扩展机制**:
- **策略工厂**：
  - v1: 字符串键策略工厂（平台 × 资源类型）
  - v2: 枚举键策略工厂（类型安全）
- **DeployListener**：部署生命周期钩子
  - ImageDeployListener: 处理镜像 URL、证书、JVM 参数
  - ConfigArtifactDeployListener: 处理配置制品
  - DuImageBomListener: 记录 OBOM
- **注解参数注入**：@Config、@ResourceConfig、@AttrConfig
- **资源策略**：按平台和资源类型选择不同的创建/删除逻辑

**Builder 当前实现**:
- **硬编码逻辑**：部署逻辑写死在 worker.py 中
- **无扩展点**：无法在部署前后插入自定义逻辑
- **无策略模式**：不同环境的差异通过 if/else 处理

**影响**:
- 无法扩展新的资源类型
- 无法定制部署流程
- 代码耦合度高，难以维护

## 三、全面改进方案

### 3.1 配置体系重构

#### 改进 1: 引入多维度配置模型

**新配置模型**:
```python
class ConfigDimension(Enum):
    STAGE = "stage"  # init / app
    TYPE = "type"    # default / service / environment / project / platform
    KIND = "kind"    # common / secret
    PROCESS = "process"  # env / file / template

class ConfigEntry:
    id: int
    scope_type: str  # platform / project / environment / service
    scope_id: int
    stage: str  # init / app
    type: int  # 优先级: 7(platform_secret) > 6(platform_common) > ... > 2(default_common) > 1(feature)
    kind: str  # common / secret
    process_type: str  # env / file / template
    key: str
    value: str
    locked: bool  # 是否锁定（下层不能覆盖）
    version: int
```

**配置优先级**:
```
Platform Secret (7) - 平台层强制敏感配置
Platform Common (6) - 平台层强制普通配置
Project Secret (5) - 项目层敏感配置
Project Common (4) - 项目层普通配置
Environment Secret (5) - 环境层敏感配置
Environment Common (4) - 环境层普通配置
Service Secret (3) - 服务层敏感配置
Service Common (2) - 服务层普通配置
Default (1) - 默认值
```

**实现**:
```python
def resolve_config_with_priority(
    service_id: int,
    stage: str = "app"
) -> Dict[str, ConfigValue]:
    """解析配置，按优先级覆盖"""
    # 1. 加载所有层级的配置
    configs = []
    configs.extend(load_platform_configs(stage))
    configs.extend(load_project_configs(service.project_id, stage))
    configs.extend(load_environment_configs(service.namespace_id, stage))
    configs.extend(load_service_configs(service_id, stage))
    
    # 2. 按优先级排序
    configs.sort(key=lambda c: (c.type, c.scope_order))
    
    # 3. 合并，高优先级覆盖低优先级
    result = {}
    locked_keys = set()
    
    for config in configs:
        if config.key in locked_keys:
            continue  # 被锁定，不能覆盖
        
        result[config.key] = ConfigValue(
            value=config.value,
            source=f"{config.scope_type}/{config.scope_id}",
            type=config.type,
            kind=config.kind,
            process_type=config.process_type,
        )
        
        if config.locked:
            locked_keys.add(config.key)
    
    return result
```

#### 改进 2: 完整的 ConfigMap/Secret 生成

**新生成逻辑**:
```python
def generate_config_objects(
    service: Service,
    config: Dict[str, ConfigValue],
    resources: List[ResourceBinding]
) -> ConfigObjects:
    """生成完整的 ConfigMap 和 Secret 对象"""
    
    # 1. 分类配置
    env_vars = {}  # 环境变量
    config_files = {}  # 配置文件
    secret_env = {}  # 敏感环境变量
    secret_files = {}  # 敏感文件
    
    for key, value in config.items():
        if value.process_type == "env":
            if value.kind == "secret":
                secret_env[key] = value.value
            else:
                env_vars[key] = value.value
        elif value.process_type == "file":
            if value.kind == "secret":
                secret_files[key] = value.value
            else:
                config_files[key] = value.value
    
    # 2. 添加资源导出
    for binding in resources:
        exports = compute_resource_exports(binding)
        env_vars.update(exports.get("env", {}))
        secret_env.update(exports.get("secret_env", {}))
    
    # 3. 生成 ConfigMap
    configmaps = []
    
    # 3.1 application-config (业务配置文件)
    if config_files:
        configmaps.append({
            "apiVersion": "v1",
            "kind": "ConfigMap",
            "metadata": {
                "name": f"{service.name}-config",
                "namespace": service.namespace,
            },
            "data": config_files,
        })
    
    # 3.2 env-config (环境变量)
    if env_vars:
        configmaps.append({
            "apiVersion": "v1",
            "kind": "ConfigMap",
            "metadata": {
                "name": f"{service.name}-env",
                "namespace": service.namespace,
            },
            "data": env_vars,
        })
    
    # 4. 生成 Secret
    secrets = []
    
    # 4.1 application-secret (敏感配置文件)
    if secret_files:
        secrets.append({
            "apiVersion": "v1",
            "kind": "Secret",
            "metadata": {
                "name": f"{service.name}-secret",
                "namespace": service.namespace,
            },
            "type": "Opaque",
            "stringData": secret_files,
        })
    
    # 4.2 env-secret (敏感环境变量)
    if secret_env:
        secrets.append({
            "apiVersion": "v1",
            "kind": "Secret",
            "metadata": {
                "name": f"{service.name}-env-secret",
                "namespace": service.namespace,
            },
            "type": "Opaque",
            "stringData": secret_env,
        })
    
    return ConfigObjects(
        configmaps=configmaps,
        secrets=secrets,
    )
```

**配置更新策略**:
```python
class ConfigEffectStrategy(Enum):
    RESTART_POD = "restart"  # 重启 Pod（修改 Deployment）
    UPDATE_CONFIGMAP = "update_configmap"  # 更新 ConfigMap（应用需支持热更新）
    UPDATE_SECRET = "update_secret"  # 更新 Secret
    REDEPLOY = "redeploy"  # 完整重新发布

def apply_config_changes(
    service_id: int,
    changes: List[ConfigChange]
) -> ConfigEffectResult:
    """应用配置变更"""
    
    # 1. 分析变更影响
    strategies = set()
    for change in changes:
        if change.process_type == "file":
            strategies.add(ConfigEffectStrategy.RESTART_POD)
        elif change.kind == "secret":
            strategies.add(ConfigEffectStrategy.UPDATE_SECRET)
        else:
            strategies.add(ConfigEffectStrategy.UPDATE_CONFIGMAP)
    
    # 2. 选择最高优先级策略
    if ConfigEffectStrategy.RESTART_POD in strategies:
        # 修改 Deployment，触发滚动更新
        patch_deployment_restart(service_id)
    elif ConfigEffectStrategy.UPDATE_SECRET in strategies:
        # 更新 Secret
        update_secrets(service_id, changes)
    elif ConfigEffectStrategy.UPDATE_CONFIGMAP in strategies:
        # 更新 ConfigMap
        update_configmaps(service_id, changes)
    
    return ConfigEffectResult(
        strategy=max(strategies, key=lambda s: s.value),
        affected_keys=[c.key for c in changes],
    )
```

```python
class ResourceRequest:
    """资源申请配置"""
    resource_type: str
    name_pattern: str  # 命名模板，如 "{service}-schema"
    attributes: Dict[str, Any]  # 属性模板
    parent_binding: Optional[str]  # 父资源绑定别名

def request_resource_on_deploy(
    service: Service,
    config: Dict[str, Any],
) -> List[ResourceBinding]:
    """部署时自动申请资源"""
    
    # 从配置中读取资源申请
    resource_requests = config.get("resource_requests", [])
    
    bindings = []
    for request in resource_requests:
        # 1. 检查是否已存在
        existing = find_resource(
            scope_type="environment",
            scope_id=service.namespace_id,
            type=request.resource_type,
            name=request.name_pattern.format(service=service.name),
        )
        
        if existing:
            # 已存在，直接绑定
            binding = bind_resource(service.id, existing.id, request.alias)
            bindings.append(binding)
            continue
        
        # 2. 创建资源
        parent_resource_id = None
        if request.parent_binding:
            parent_binding = get_service_binding(service.id, request.parent_binding)
            parent_resource_id = parent_binding.resource_id
        
        resource = create_resource(
            scope_type="environment",
            scope_id=service.namespace_id,
            type=request.resource_type,
            name=request.name_pattern.format(service=service.name),
            attributes=render_attributes(request.attributes, {
                "service": service,
                "config": config,
            }),
            parent_resource_id=parent_resource_id,
            created_by=get_current_user_id(),
        )
        
        # 3. 绑定资源
        binding = bind_resource(service.id, resource.id, request.alias)
        bindings.append(binding)
        
        # 4. 执行初始化脚本（如创建数据库 Schema）
        if request.init_script:
            execute_init_script(resource, request.init_script)
    
    return bindings
```

```python
class DeploymentPipeline:
    """部署流程编排"""
    
    def execute(
        self,
        service_id: int,
        image_digest: str,
        deployment_id: int,
    ) -> DeploymentResult:
        """执行完整的部署流程"""
        
        # ===== 阶段 0: 环境上下文设置 =====
        context = self._setup_context(service_id)
        
        # ===== 阶段 1: 参数装配 =====
        params = self._assemble_params(
            service_id=service_id,
            stage="app",
            context=context,
        )
        
        # ===== 阶段 2: 副作用执行 =====
        self._execute_side_effects(
            service_id=service_id,
            params=params,
            listeners=[
                CertificateListener(),  # 读取证书
                ResourceBindingListener(),  # 验证资源绑定
                ResourceRequestListener(),  # 自动申请资源
                ImageUrlListener(),  # 生成镜像 URL
                ConfigValidationListener(),  # 验证配置完整性
            ],
        )
        
        # ===== 阶段 3: 客户端初始化 =====
        k8s_client = self._init_k8s_client(
            service_id=service_id,
            params=params,
        )
        
        # ===== 阶段 4: 两阶段渲染 =====
        manifests = self._render_manifests(
            service_id=service_id,
            image_digest=image_digest,
            params=params,
            deployment_id=deployment_id,
        )
        
        # ===== 阶段 5: K8s 对象提交 =====
        apply_results = self._apply_manifests(
            k8s_client=k8s_client,
            manifests=manifests,
        )
        
        # ===== 阶段 6: 状态查询 =====
        status = self._wait_for_ready(
            k8s_client=k8s_client,
            service_id=service_id,
            timeout=600,
        )
        
        # ===== 阶段 7: OBOM 记录 =====
        self._record_obom(
            deployment_id=deployment_id,
            params=params,
            manifests=manifests,
            apply_results=apply_results,
        )
        
        return DeploymentResult(
            success=status.ready,
            manifests=manifests,
            status=status,
        )
    
    def _assemble_params(
        self,
        service_id: int,
        stage: str,
        context: DeploymentContext,
    ) -> Dict[str, Any]:
        """参数装配（五级覆盖）"""
        
        params = {}
        
        # 1. Feature 参数（最低优先级）
        params.update(self._get_feature_params())
        
        # 2. 资源参数
        params.update(self._get_resource_params(service_id))
        
        # 3. DU 属性参数（服务属性）
        params.update(self._get_service_attributes(service_id))
        
        # 4. 配置参数（三层覆盖：default < service < environment < project < platform）
        config = resolve_config_with_priority(service_id, stage)
        params.update(self._config_to_params(config))
        
        # 5. 证书参数（最高优先级）
        params.update(self._get_certificate_params(context.namespace_id))
        
        return params
    
    def _render_manifests(
        self,
        service_id: int,
        image_digest: str,
        params: Dict[str, Any],
        deployment_id: int,
    ) -> List[Dict[str, Any]]:
        """两阶段渲染"""
        
        # 阶段 1: 渲染 values.yaml
        values_template = self._load_template("values.yaml.j2")
        values_yaml = values_template.render(**params)
        values = yaml.safe_load(values_yaml)
        
        # 阶段 2: 渲染各个 K8s 对象模板
        manifests = []
        
        # 2.1 ConfigMap 和 Secret
        config_objects = generate_config_objects(
            service_id=service_id,
            config=params["config"],
            resources=params["resources"],
        )
        manifests.extend(config_objects.configmaps)
        manifests.extend(config_objects.secrets)
        
        # 2.2 Deployment
        deployment_template = self._load_template("deployment.yaml.j2")
        deployment = yaml.safe_load(deployment_template.render(
            values=values,
            deployment_id=deployment_id,
            image_digest=image_digest,
            restarted_at=utcnow().isoformat(),
            **params,
        ))
        manifests.append(deployment)
        
        # 2.3 Service
        service_template = self._load_template("service.yaml.j2")
        service = yaml.safe_load(service_template.render(
            values=values,
            **params,
        ))
        manifests.append(service)
        
        # 2.4 Ingress
        if params["service"]["ingress_enabled"]:
            ingress_template = self._load_template("ingress.yaml.j2")
            ingress = yaml.safe_load(ingress_template.render(
                values=values,
                **params,
            ))
            manifests.append(ingress)
        
        # 2.5 HPA
        if params["service"]["hpa_enabled"]:
            hpa = generate_hpa(params["service"], values)
            if hpa:
                manifests.append(hpa)
        
        # 2.6 PDB
        if params["service"]["pdb_enabled"]:
            pdb = generate_pdb(params["service"], values)
            if pdb:
                manifests.append(pdb)
        
        # 2.7 ServiceMonitor
        if params["service"]["monitoring_enabled"]:
            service_monitor = generate_service_monitor(params["service"], values)
            if service_monitor:
                manifests.append(service_monitor)
        
        return manifests
    
    def _apply_manifests(
        self,
        k8s_client: K8sClient,
        manifests: List[Dict[str, Any]],
    ) -> List[ApplyResult]:
        """提交 K8s 对象（先 GET 再 create/update）"""
        
        results = []
        
        for manifest in manifests:
            kind = manifest["kind"]
            name = manifest["metadata"]["name"]
            namespace = manifest["metadata"]["namespace"]
            
            # 1. 先 GET 检查是否存在
            existing = k8s_client.get(
                kind=kind,
                name=name,
                namespace=namespace,
            )
            
            if existing:
                # 2a. 已存在，执行 update
                manifest["metadata"]["resourceVersion"] = existing["metadata"]["resourceVersion"]
                result = k8s_client.update(
                    kind=kind,
                    name=name,
                    namespace=namespace,
                    body=manifest,
                )
                
                # 2b. 如果是 Deployment，patch restartedAt 触发滚动更新
                if kind == "Deployment":
                    k8s_client.patch(
                        kind=kind,
                        name=name,
                        namespace=namespace,
                        body={
                            "spec": {
                                "template": {
                                    "metadata": {
                                        "annotations": {
                                            "kubectl.kubernetes.io/restartedAt": utcnow().isoformat(),
                                        },
                                    },
                                },
                            },
                        },
                    )
                
                results.append(ApplyResult(
                    kind=kind,
                    name=name,
                    action="updated",
                    object=result,
                ))
            else:
                # 3. 不存在，执行 create
                result = k8s_client.create(
                    kind=kind,
                    namespace=namespace,
                    body=manifest,
                )
                
                results.append(ApplyResult(
                    kind=kind,
                    name=name,
                    action="created",
                    object=result,
                ))
        
        return results
    
    def _wait_for_ready(
        self,
        k8s_client: K8sClient,
        service_id: int,
        timeout: int,
    ) -> DeploymentStatus:
        """等待 Deployment 就绪（完整检查）"""
        
        service = get_service(service_id)
        start_time = time.time()
        
        while time.time() - start_time < timeout:
            # 1. 获取 Deployment 状态
            deployment = k8s_client.get(
                kind="Deployment",
                name=service.name,
                namespace=service.namespace,
            )
            
            # 2. 检查 observedGeneration
            observed_generation = deployment.get("status", {}).get("observedGeneration")
            metadata_generation = deployment.get("metadata", {}).get("generation")
            
            if observed_generation != metadata_generation:
                # 还没有观察到最新版本，继续等待
                time.sleep(5)
                continue
            
            # 3. 检查副本数
            spec_replicas = deployment.get("spec", {}).get("replicas", 0)
            status = deployment.get("status", {})
            updated_replicas = status.get("updatedReplicas", 0)
            available_replicas = status.get("availableReplicas", 0)
            
            if updated_replicas != spec_replicas:
                # 还有副本没有更新，继续等待
                time.sleep(5)
                continue
            
            if available_replicas != spec_replicas:
                # 还有副本不可用，继续等待
                time.sleep(5)
                continue
            
            # 4. 检查 Progressing 条件
            conditions = status.get("conditions", [])
            progressing_condition = next(
                (c for c in conditions if c["type"] == "Progressing"),
                None
            )
            
            if progressing_condition and progressing_condition["status"] == "False":
                # 进度失败
                return DeploymentStatus(
                    ready=False,
                    reason=progressing_condition.get("reason", "Unknown"),
                    message=progressing_condition.get("message", ""),
                )
            
            # 5. 所有检查通过，部署成功
            return DeploymentStatus(
                ready=True,
                replicas=spec_replicas,
                updated_replicas=updated_replicas,
                available_replicas=available_replicas,
            )
        
        # 超时
        return DeploymentStatus(
            ready=False,
            reason="Timeout",
            message=f"Deployment did not become ready within {timeout} seconds",
        )
    
    def _record_obom(
        self,
        deployment_id: int,
        params: Dict[str, Any],
        manifests: List[Dict[str, Any]],
        apply_results: List[ApplyResult],
    ) -> None:
        """记录 OBOM（部署物料清单）"""
        
        # 1. 记录配置快照
        store_deployment_config_snapshot(
            deployment_id=deployment_id,
            config=params["config"],
        )
        
        # 2. 记录资源绑定快照
        store_deployment_resource_snapshot(
            deployment_id=deployment_id,
            resources=params["resources"],
        )
        
        # 3. 记录生成的 K8s 对象
        store_deployment_manifests(
            deployment_id=deployment_id,
            manifests=manifests,
        )
        
        # 4. 记录应用结果
        store_deployment_apply_results(
            deployment_id=deployment_id,
            apply_results=apply_results,
        )
```

```python
class DeploymentDependency:
    """部署依赖关系"""
    
    @staticmethod
    def get_dependencies(deployment_id: int) -> List[int]:
        """获取部署任务的依赖"""
        
        deployment = get_deployment(deployment_id)
        dependencies = []
        
        # 规则 1: 配置部署必须在应用部署之前
        if deployment.artifact_type == "image":
            # 查找同一服务的 config 部署
            config_deployments = find_pending_deployments(
                service_id=deployment.service_id,
                artifact_types=["config_global", "config_secret"],
            )
            dependencies.extend([d.id for d in config_deployments])
        
        # 规则 2: 资源申请必须在应用部署之前
        if deployment.has_resource_requests:
            # 等待资源申请完成
            resource_deployments = find_pending_deployments(
                service_id=deployment.service_id,
                artifact_types=["resource_request"],
            )
            dependencies.extend([d.id for d in resource_deployments])
        
        # 规则 3: 用户自定义依赖
        dependencies.extend(deployment.manual_dependencies)
        
        return dependencies
    
    @staticmethod
    def can_start(deployment_id: int) -> bool:
        """检查部署任务是否可以开始"""
        
        dependencies = DeploymentDependency.get_dependencies(deployment_id)
        
        for dep_id in dependencies:
            dep = get_deployment(dep_id)
            if dep.status not in ["success", "skipped"]:
                return False
        
        return True

class DeploymentScheduler:
    """部署调度器"""
    
    def __init__(self):
        self.queue = PriorityQueue()
        self.running = {}
        self.lock = threading.Lock()
    
    def enqueue(self, deployment_id: int, priority: int = 0):
        """将部署任务加入队列"""
        
        deployment = get_deployment(deployment_id)
        
        # 检查并发限制
        service_id = deployment.service_id
        if service_id in self.running:
            # 同一服务已有任务在运行，等待
            update_deployment_status(deployment_id, "queued", "等待前序任务完成")
            return
        
        # 检查依赖
        if not DeploymentDependency.can_start(deployment_id):
            update_deployment_status(deployment_id, "queued", "等待依赖任务完成")
            return
        
        # 加入队列
        self.queue.put((priority, deployment.created_at, deployment_id))
        update_deployment_status(deployment_id, "queued", "排队中")
    
    def schedule(self):
        """调度器主循环"""
        
        while True:
            try:
                # 从队列中取出任务
                priority, created_at, deployment_id = self.queue.get(timeout=5)
                
                # 再次检查依赖（可能有变化）
                if not DeploymentDependency.can_start(deployment_id):
                    # 依赖未满足，重新入队
                    self.queue.put((priority, created_at, deployment_id))
                    time.sleep(1)
                    continue
                
                # 标记为运行中
                deployment = get_deployment(deployment_id)
                with self.lock:
                    self.running[deployment.service_id] = deployment_id
                
                # 执行部署
                try:
                    pipeline = DeploymentPipeline()
                    result = pipeline.execute(
                        service_id=deployment.service_id,
                        image_digest=deployment.image_digest,
                        deployment_id=deployment_id,
                    )
                    
                    if result.success:
                        update_deployment_status(deployment_id, "success", "部署成功")
                    else:
                        update_deployment_status(deployment_id, "failed", result.error)
                
                finally:
                    # 移除运行标记
                    with self.lock:
                        del self.running[deployment.service_id]
                    
                    # 唤醒等待的任务
                    self._wakeup_waiting_tasks(deployment.service_id)
            
            except Empty:
                continue
            except Exception as e:
                logger.error(f"部署任务执行失败: {e}")
    
    def _wakeup_waiting_tasks(self, service_id: int):
        """唤醒等待的任务"""
        
        waiting_deployments = find_pending_deployments(service_id=service_id)
        for deployment in waiting_deployments:
            if DeploymentDependency.can_start(deployment.id):
                self.enqueue(deployment.id, deployment.priority)
```

```python
class ResourceStrategy(ABC):
    """资源策略接口"""
    
    @abstractmethod
    def create(self, resource: Resource) -> Dict[str, Any]:
        """创建资源"""
        pass
    
    @abstractmethod
    def delete(self, resource: Resource) -> None:
        """删除资源"""
        pass
    
    @abstractmethod
    def validate(self, attributes: Dict[str, Any]) -> None:
        """验证资源属性"""
        pass

class ResourceStrategyFactory:
    """资源策略工厂"""
    
    _strategies: Dict[Tuple[str, str], Type[ResourceStrategy]] = {}
    
    @classmethod
    def register(
        cls,
        platform: str,
        resource_type: str,
        strategy: Type[ResourceStrategy],
    ) -> None:
        """注册策略"""
        cls._strategies[(platform, resource_type)] = strategy
    
    @classmethod
    def get_strategy(
        cls,
        platform: str,
        resource_type: str,
    ) -> ResourceStrategy:
        """获取策略"""
        
        # 先查找精确匹配
        key = (platform, resource_type)
        if key in cls._strategies:
            return cls._strategies[key]()
        
        # 再查找通配
        key = ("*", resource_type)
        if key in cls._strategies:
            return cls._strategies[key]()
        
        raise ValueError(f"No strategy found for {platform}/{resource_type}")

# 注册策略示例
@ResourceStrategyFactory.register("huawei", "gauss_schema")
class HuaweiGaussSchemaStrategy(ResourceStrategy):
    """华为云 GaussDB Schema 策略"""

        """创建 Schema"""
        
        # 1. 获取父资源（GaussDB）
        parent = get_resource(resource.parent_resource_id)
        
        # 2. 连接数据库
        conn = psycopg2.connect(
            host=parent.attributes["host"],
            port=parent.attributes["port"],
            user=parent.attributes["username"],
            password=parent.attributes["password"],
            database=parent.attributes["database"],
        )
        
        # 3. 创建 Schema
        cursor = conn.cursor()
        cursor.execute(f"CREATE SCHEMA IF NOT EXISTS {resource.attributes['schema']}")
        conn.commit()
        
        # 4. 返回结果
        return {
            "schema": resource.attributes["schema"],
            "created": True,
        }
    
    def delete(self, resource: Resource) -> None:
        """删除 Schema"""
        
        parent = get_resource(resource.parent_resource_id)

            host=parent.attributes["host"],

            password=parent.attributes["password"],
            database=parent.attributes["database"],
        )
        
        cursor = conn.cursor()
        cursor.execute(f"DROP SCHEMA IF EXISTS {resource.attributes['schema']} CASCADE")
```

## 五、总结

通过深度分析 XAC 的设计，我们发现 Builder 平台在以下方面存在重大缺陷：

1. **配置体系**: 缺少多维度配置模型、ConfigMap/Secret 生成不完整、配置生效机制不明确
2. **模板体系**: 单阶段渲染、K8s 对象生成不完整、模板字段不完整
3. **资源管理**: 资源类型不完整、不支持资源自动申请、缺少策略模式
4. **部署引擎**: 缺少完整的部署流程、无依赖管理、就绪判断不完整、无 OBOM 记录
5. **可扩展性**: 无扩展点机制、无 Listener 模式、无策略工厂

本改进方案基于 XAC 的最佳实践，提出了系统性的重构方案，预计需要 **10-15 周**完成。改进后的系统将具备：

- **完整的配置体系**: 多维度配置、4 类 ConfigMap/Secret、明确的生效机制
- **强大的模板系统**: 两阶段渲染、7 种 K8s 对象、完整的字段定义
- **灵活的资源管理**: 15+ 种资源类型、自动申请、策略模式
- **可靠的部署引擎**: 7 阶段流程、依赖管理、完整的就绪判断、OBOM 记录
- **高可扩展性**: Listener 机制、策略工厂、清晰的扩展点

这将使 Builder 平台达到企业级 PaaS 平台的标准。
