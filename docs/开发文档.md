# SWR 镜像构建平台开发文档

版本：v1.3.0-dev.1。本文面向继续维护项目的后端、前端及运维开发人员。v1.1.1 内容作为既有构建与 HCS 模块参考。

## v1.2 开发状态

已实现项目/SWR 前缀范围、项目/命名空间 role binding、默认拒绝路由、kubeconfig 静态凭据加密、namespace 纳管与 SSAR 自检、image-only 服务 revision、Secret 版本、审批与 SQLite 服务发布队列。服务 worker 固定镜像 digest，使用 lease/fencing 检查，并等待 Deployment UID、发布 annotation 和副本就绪状态。

Namespace 冻结截止时间和部署窗口会在 API 入队、worker 执行前分别检查。窗口使用 IANA 时区与 ISO 星期编号 1–7；跨午夜区间归属开始日，队列等待期间策略更新会在外部写入前生效。

资源页可创建与编辑 namespace 审批、冻结和部署窗口策略；策略保存要求 `cluster.manage`。

集群纳管支持粘贴单文件 kubeconfig `apiVersion: v1` / `kind: Config`，按 `current-context` 解析静态 Token 或内嵌客户端证书/私钥；系统设置也可上传 PEM 客户端证书、私钥和可选 CA。解析后的凭据加密存储。为避免在服务端执行配置指定代码，不支持 `exec` / `auth-provider`、用户名密码或配置文件外部凭据路径。worker 支持 image-only Deployment 更新。CCE 证书签发、用户组/SSO、managed 资源渲染及 SSA、生产级告警/灾备、真实 HCS/CCE/Kubernetes 联调仍待完成；未知的外部写入状态会标记 `unknown`，需要人工核对。

## 1. 交付范围与限制

已实现：镜像累加/全量构建、登录、旧账号设置、v1.2 项目/namespace scope 授权、kubeconfig Token/客户端证书接入、服务 revision、审批和持久化 image-only worker。旧部署目标只保留迁移查看/测试，执行接口和构建自动触发已禁用。

**仍未实现：旧式 Credential 签名、ManageOne SSO、CCE 证书签发/撤销、用户组和机器人账号、managed 工作负载渲染及 SSA、灰度、自动回滚、pods/log API、真实云端联调。**

HCS 默认 AK/SK 模式已经实现：官方 SDK 对最终请求字节签名、换 Token、作用域/有效期校验及缓存；没有接入真实用户环境。默认空体加作用域头，现场需要 JSON 时显式配置模板，不伪造 identity 方法或 SK 字段。详见《华为云Stack8.5.1接口接入设计.md》。

## 2. 本地开发环境

要求：Python 3.11+，Linux（构建功能依赖 Docker），浏览器。单元及端到端测试使用模拟仓库和假 Docker，无需真实云凭证。

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
cp config.example.yaml config.yaml
# 配置 registry 或在登录后由管理员通过系统设置维护
python -m swr_builder -c config.yaml
```

打开 `http://127.0.0.1:8080`。首次 admin 的密码为空时，从 `data/admin-initial-password.txt` 读取，首次登录需修改。也可在首次启动前配置 `BUILDER_ADMIN_PASSWORD`；已有账号不会被该环境变量重置。

不要提交 config.yaml、*.env、data、真实凭证、Token 或生产日志。生产使用 HTTPS 和 `server.secure_cookie: true`。只运行一个进程/worker。

## 4. 应用组装与生命周期

`create_app(settings=None, registry_transport=None, deploy_transport=None, hcs_transport=None)` 提供测试注入点。生产不传 transport。

1. 初始化 Store，自动追加迁移，创建/读取加密主密钥。
2. SysConfig 加载数据库覆盖项，环境变量锁定项不被覆盖。
3. 组装 RegistryClient、EventBus、BuildManager、AuthService、DeployManager。
4. 对象在 `app.state.ctx` 中集中访问；兼容 `app.state.store/settings/manager`。
5. lifespan 创建首个管理员、标记重启遗留任务、启动构建管理器、导入首次应用。
6. 停止时取消构建、等待事件、停止部署并关闭 HTTP 客户端。

禁止在 import 时连接真实云服务或自动执行部署。HCS 默认关闭；认证测试需要管理员主动触发。

## 5. 请求认证与权限

公共路由仅包括 `/login`、`/healthz`、静态资源、登录提交及站点公开配置。其他路由需要会话或 API Token。

- 网页：随机会话令牌放 HttpOnly / SameSite=Lax Cookie，数据库仅存摘要。
- 自动化：`Authorization: Bearer <token>`，继承账号实时角色。
- Cookie 身份的修改请求要求 `X-Requested-With: XMLHttpRequest`；前端 `api()` 与上传 XHR 已统一添加。
- 未登录 API 返回 401，页面跳转登录；没有权限返回 403。
- 首次/重置密码后，仅允许查询自身、退出及改密等必要 API。
- 固定角色见 `auth.py` 的 `ROLE_PERMISSIONS`；路由授权见 `main.py` 的 `route_permission()`。
- 修改密码会撤销其他会话和全部 API 令牌；管理员重置密码会撤销该账号全部会话与令牌。

新增 API 必须同时补充服务端授权。不要仅用 `data-perm` 隐藏前端按钮；不要把未登记路径误当作“默认管理员可见”。构建取消还需检查任务提交者，部署目标修改需要 deploy.manage。

## 6. 设置与秘密值

新增设置步骤：

1. 在 config.py 对应 dataclass 加默认值（HCSProfile 定义在 cloud/hcs.py）。
2. 在 sysconfig.py 的 FIELDS 登记字段、类型、标签、范围及提示。
3. 如需环境变量，登记 ENV_OVERRIDES；页面会显示 locked_by。
4. 加 `_convert()` 校验和必要的跨字段校验。
5. 若影响运行组件，订阅 `SysConfig.on_change`；异常必须回滚运行配置，持久化成功后才视为保存完成。
6. 添加测试：持久化/重启、非法值、秘密值不回显、环境锁定、失败恢复。

优先级：环境变量 > settings 表 > YAML/默认值。secret 字段空字符串默认不修改，只有明确的 clear 列表才清空。秘密值用 cryptography.Fernet 加密（enc:v2），主密钥与数据库必须一起备份。旧 enc:v1 仅为开发数据兼容读取，新写入不再使用。

不要日志输出密码、SK、Token、请求 Authorization 或云端原始错误响应。审计记录动作、目标及变化的字段名，不保存秘密值。

## 7. 数据库与升级

SQLite WAL；Store 方法通过进程内锁和短事务访问。不要在事务中等待网络请求。

| 表 | 用途 |
| --- | --- |
| apps / jobs | 应用 JSON、构建快照、镜像与版本、状态及提交者 |
| users | 密码哈希、角色、状态、强制改密 |
| sessions / api_tokens | 令牌摘要、有效期及活跃信息 |
| settings | 设置值及修改信息，敏感值为密文 |
| audit_logs | 登录及管理操作摘要 |
| deploy_targets | 类型、绑定应用、开关、加密配置 |
| deployments | 目标/应用/构建、镜像、触发方式、状态、消息及时间 |

v1.0 → v1.1 为追加表/字段迁移，不删除历史 apps/jobs。已有历史任务 created_by 为空时，开发者不能按“自己的任务”取消，管理员仍可处理。

后续迁移应显式检查 schema、可重复执行、先备份；不要依赖覆盖式建表或自动删除字段。回退旧程序前应恢复升级前备份，而不是假设新 schema 可无损降级。

## 8. 构建流程与扩展

上传 → 安全保存 → 创建 queued 任务 → 全局信号量 → 同仓库锁 → 执行时重新解析版本 → Docker login/build → 架构校验 → push → 成功事件。

任务保存提交时应用快照，防止构建过程中修改应用影响任务。仓库及构建设置在存在未完成构建时禁止修改。Docker 命令使用参数数组，不经过 Shell；登录密码走 stdin。

事件名称：`build.succeeded`、`build.failed`、`deploy.succeeded`、`deploy.failed`。载荷分别为 `{"job": ...}`、`{"deployment": ...}`。订阅者不得反向修改构建已完成结果。通知/安全扫描需要持久化、重试和去重时应接入任务队列，当前事件总线不是可靠消息中间件。

## 9. 添加部署适配器

```python

    type = "example"
    label = "示例发布系统"
    description = "仅为扩展示例，不是可直接上线的实现"
    fields = [FieldSpec("endpoint", "服务地址", required=True),
              FieldSpec("token", "访问令牌", "secret", True)]

    async def test(self, config, transport=None):
        # 校验网络和最小必要权限；不要用真实发布作为无提示的连接测试
        raise NotImplementedError

    async def deploy(self, ctx):
        # ctx.image/job/app/config/operator/log/transport 可用
        # 明确区分“请求已接受”和“工作负载已就绪”
        raise NotImplementedError

register(ExampleDeployer())
```

适配器还需：输入校验、TLS、凭证隔离、超时、取消处理、日志脱敏、测试 transport 和真实环境验收。manager 负责记录和目标锁；前端根据 FieldSpec 渲染表单。新增回滚实现应明确回滚镜像、配置、依赖及数据库的边界，不能仅将旧镜像 PATCH 称为完整回滚。

Webhook 签名对发送的原始字节计算，接收端自行验证 `X-SWR-Signature`，按 deployment_id 去重。ping 会真正发出请求，接收端必须区分事件类型。

Kubernetes 使用 Deployment strategic merge patch，检查容器存在；可等待 observedGeneration 和副本数。现场必须预先配置拉取 SWR 的 imagePullSecrets，并确认目标节点架构和探针。

## 10. HCS 后端兼容模块（可选）

HCS 认证与只读 API 模块和 Kubernetes 发布相互独立，不是部署前置条件；系统设置界面不再展示 HCS 配置，默认也不会发起云端请求。以下实现说明用于维护保留的兼容代码。

HCS 兼容代码使用独立的 SWR/HCS/Kubernetes 凭证域；Kubernetes 发布只读取系统设置保存的 kubeconfig 凭据，不读取或要求 HCS AK/SK、IAM Token 或 CCE Endpoint。

### 10.1 签名与请求

`cloud/signing.py` 调用华为官方 `huaweicloudsdkcore==3.1.219` 的 `Signer(BasicCredentials(...))`；只使用签名器，不调用可能自动发现项目的完整 SDK Client。签名 URL 固定在配置 IAM Endpoint 下的 `/v3/auth/tokens`，TLS 默认校验、禁止重定向。

对实际发送字节计算 body hash；签名覆盖 Host（含端口）、Content-Type、Content-Length、UTC X-Sdk-Date、X-Project-Id 或 X-Domain-Id。临时凭证可加入 X-Security-Token，并纳入签名。默认零字节空体，不自行发明 identity 方法。

`aksk_request_body` 支持显式 JSON 对象模板。完整字符串值 `${ak}`、`${project_id}`、`${domain_id}` 解析后替换，再统一序列化 UTF-8 并签名；不拼接 JSON、不支持 `${sk}`、拒绝 SK/密码字段。模板属于现场协议配置，不宣称所有网关需要同一种 body。

当前使用官方 SDK-HMAC-SHA256 / Access 授权格式；旧式 Credential 签名需单独按官方兼容算法适配，不能仅替换头字符串。模板无法补救签名算法不兼容，遇到该情况必须明确报错。

### 10.2 Token 生命周期

200/201 必须有 X-Subject-Token 和 token JSON 对象；若配置作用域 ID，响应必须匹配该项目/账号，否则不缓存。已过期或即将过期的 Token 拒绝使用。

单客户端并发换 Token 使用锁合并；缓存提前 60 秒失效；没有过期时间则不重复使用缓存。只读服务请求 401 后最多重新认证并重试一次，不重放写操作。认证失败不自动回退密码。

### 10.3 可选配置与诊断

兼容 API 的字段仍由 `cloud/hcs.py` 和配置文件/环境变量读取；它们不出现在系统设置界面，也不会在 Kubernetes 发布中使用。

CLI `python -m swr_builder.cloud -c config.yaml` 仅用于维护现有 HCS 兼容代码；部署 kubeconfig 时不需要运行该诊断。

### 10.4 测试与服务扩展

`tests/test_hcs_aksk.py` 使用独立服务端签名校验、临时凭证、JSON 字节长度、scope、过期/错误/重定向、并发缓存、401 刷新及 API 秘密值测试。`tests/signing_vectors.json` 包含由官方独立示例 SDK 生成的固定签名，全部为虚拟凭证。

真实网关仍需验收 Endpoint、签名版本、请求体与权限。SWR/CCE/ECS 业务 API 的路径、分页、区域差异、限流及错误码按现场组件文档实现，不开放前端任意 API 代理。

## 11. API 开发约定

- 返回 JSON；可预期输入错误 400，未登录 401，越权 403，不存在 404，云服务上游错误按现有约定处理。
- 用户可见的错误要可操作但不含凭证、原始云响应或内部堆栈。
- 所有列表接口有界分页；SQL 绑定参数，不拼接用户值。
- 变更记录审计；网络写操作保留可追踪任务 ID，说明超时后的不确定状态。
- POST 创建任务返回 ID，前端增量读日志，不用长时间占用一个 HTTP 请求等待完成。
- 当前 API 范围见 README 与系统设计的接口表；交互式 OpenAPI 由 FastAPI 提供，仍需登录。

## 13. 上线与运维

- 推荐专用构建机 + systemd 或容器单实例；Docker socket 权限等同主机高权限。
- HTTPS、Secure Cookie、网络白名单、反向代理限流；大文件上传限制同时配置代理和平台。
