# 资源管理与环境预置功能测试指南

## 测试环境准备

### 1. 数据库迁移
```bash
# 确保数据库已应用最新迁移
psql $DATABASE_URL -f migrations/009_resources.sql
```

### 2. 启动服务
```bash
# 后端
uvicorn swr_builder.main:app --reload

# 前端开发服务器
cd web && npm run dev
```

### 3. 准备测试数据
- 至少 1 个项目
- 至少 1 个应用
- 至少 1 个环境（命名空间）
- 至少 1 个用户（具有相应权限）

## 功能测试用例

### 测试 1: 创建平台级 Redis 资源

**前置条件**: 用户具有 `resource.manage` 权限

**步骤**:
1. 导航到「资源管理」页面
2. 确认在「平台资源」tab
3. 点击「创建资源」按钮
4. 填写表单：
   - 作用域类型: 平台
   - 资源类型: Redis
   - 资源名称: `platform-redis`
   - 描述: `平台级 Redis 缓存`
   - 主机: `redis.example.com`
   - 端口: `6379`
   - 密码: `test123456`
   - 数据库编号: `0`
5. 点击「保存」

**期望结果**:
- 创建成功，跳转到资源详情页
- 基本信息正确显示
- 密码显示为 `******`
- 版本显示为 v1

### 测试 2: 查看敏感信息（Reveal）

**前置条件**: 
- 完成测试 1
- 用户具有 `resource.reveal` 权限

**步骤**:
1. 在资源详情页面
2. 点击「查看敏感信息」按钮
3. 确认对话框

**期望结果**:
- 显示明文密码: `test123456`
- 其他敏感字段也显示明文

### 测试 3: 更新资源版本

**前置条件**: 完成测试 1

**步骤**:
1. 在资源详情页面
2. 点击「编辑」按钮
3. 修改端口为 `6380`
4. 填写变更说明: `更新端口配置`
5. 点击「保存」

**期望结果**:
- 更新成功
- 版本号变为 v2
- 版本历史显示 2 个版本
- 可以查看 v1 的内容（端口 6379）

### 测试 4: 创建环境级 GaussDB 资源

**前置条件**: 
- 已有环境（namespace_id: 1）
- 用户具有环境的 `resource.manage` 权限

**步骤**:
1. 导航到「资源管理」页面
2. 切换到「环境资源」tab
3. 点击「创建资源」
4. 填写表单：
   - 作用域类型: 环境
   - 环境 ID: 选择测试环境
   - 资源类型: GaussDB 数据库
   - 资源名称: `app-db`
   - 描述: `应用主数据库`
   - 主机: `gaussdb.example.com`
   - 端口: `5432`
5. 点击「保存」

**期望结果**:
- 创建成功
- 在「环境资源」tab 中显示
- 作用域显示为「环境」标签

### 测试 5: 创建子资源（GaussDB Schema）

**前置条件**: 完成测试 4

**步骤**:
1. 在「环境资源」tab
2. 点击「创建资源」
3. 填写表单：
   - 作用域类型: 环境
   - 环境 ID: 同测试 4
   - 资源类型: GaussDB Schema
   - 资源名称: `app-schema`
   - 描述: `应用 Schema`
   - 父资源: 选择 `app-db`
   - Schema 名称: `app_schema`
4. 点击「保存」

**期望结果**:
- 创建成功
- 显示父资源关系
- 可以看到父资源的属性（主机、端口继承自父资源）

### 测试 6: 服务绑定资源

**前置条件**: 
- 完成测试 1 和测试 4
- 已有一个托管服务

**步骤**:
1. 导航到服务详情页面
2. 切换到「资源绑定」tab
3. 点击「绑定资源」按钮
4. 选择资源: `platform-redis`
5. 输入别名: `cache`
6. 点击「确定」
7. 再次点击「绑定资源」
8. 选择资源: `app-db`
9. 输入别名: `db`
10. 点击「确定」

**期望结果**:
- 两个绑定都创建成功
- 列表显示 2 个绑定
- 显示资源类型、版本、作用域
- 可以点击资源名称跳转到资源详情

### 测试 7: 预览资源导出

### 测试 12: 创建环境预置

**前置条件**: 用户具有创建预置权限

**步骤**:
1. 导航到「环境预置」页面
2. 点击「创建预置」按钮
3. 填写表单：
   - 名称: `standard-web-app`
   - 描述: `标准 Web 应用预置`
   - Profile 模板:
     ```json
     {
       "naming_policy": {"template": "{{app}}-{{env}}"},
       "scheduling": {"node_selector": {}, "tolerations": []},
       "limits": {"cpu": "2", "memory": "4Gi"}
     }
     ```
   - 默认配置集:
     - 添加环境变量配置集
     - 名称: `common-env`
     - 键: `LOG_LEVEL`, 值: `INFO`
     - 键: `TZ`, 值: `Asia/Shanghai`
   - 必需资源类型: 选择 `Redis`, `GaussDB Schema`
   - 必需参数:
     - 键: `app_name`, 标签: `应用名称`, 必需: 是
     - 键: `replicas`, 标签: `副本数`, 必需: 是, 默认值: `2`
4. 点击「保存」

**期望结果**:
- 创建成功
- 跳转到预置列表
- 显示新创建的预置

### 测试 13: 编辑预置

## 故障排查

### 问题 1: 资源创建失败

**症状**: 提交表单后返回 500 错误

**排查**:
1. 检查后端日志
2. 验证数据库连接
3. 确认 migrations 已执行
4. 检查 SecretBox 密钥配置

### 问题 2: 敏感信息无法解密

**症状**: reveal 后仍显示乱码

**排查**:
1. 检查 SECRET_KEY 环境变量
2. 确认 SecretBox 实例化正确
3. 验证加密和解密使用相同的密钥

### 问题 3: 资源导出环境变量不生效

**症状**: 服务发布后容器环境变量缺失

**排查**:
1. 检查资源绑定是否创建成功
2. 验证 resolve_config() 逻辑
3. 查看 Deployment YAML 生成
4. 检查资源属性是否正确

### 问题 4: 预置应用失败

**症状**: 应用预置时报错

**排查**:
1. 检查环境是否有必需资源类型
2. 验证必需参数是否填写完整
3. 检查 profile_template 格式是否正确
4. 查看后端日志详细错误
