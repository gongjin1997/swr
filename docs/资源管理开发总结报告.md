## 核心功能实现

### 1. 数据库设计 ✅

**表结构**:
- `resources` - 资源主表
- `resource_versions` - 版本历史表
- `service_resource_bindings` - 服务资源绑定表
- `presets` - 环境预置表

**特性**:
- 多版本管理（每次更新创建新版本）
- 作用域隔离（平台/环境）
- 外键约束（防止误删除）
- 敏感信息加密存储

## 技术亮点

### 1. 安全性 🔒

- **敏感信息加密**: 使用 SecretBox 加密密码、Token、密钥
- **Reveal 权限**: 查看明文需要 `resource.reveal` 权限
- **前端掩码**: 敏感字段自动显示为 `******`
- **乐观锁**: base_version 防止并发更新冲突

### 2. 版本管理 📦

- **完整历史**: 每次更新创建新版本
- **不可变性**: 历史版本只读，不可修改
- **变更追踪**: 记录操作人、时间、变更说明
- **版本对比**: 可查看任意版本的完整内容

### 3. 资源导出 🔄

- **自动计算**: 根据资源类型定义自动生成环境变量
- **模板占位符**: 支持 `{parent.host}` 等父资源属性引用
- **父子继承**: 子资源自动继承父资源属性
- **别名前缀**: 使用别名作为环境变量前缀（如 CACHE_HOST）

### 4. 环境预置 🎯

- **Profile 模板**: 标准化环境配置（命名、调度、资源限制）
- **默认配置集**: 预设环境变量和文件
- **资源类型检查**: 验证环境是否有必需资源
- **参数化**: 支持动态参数（如应用名称、副本数）

### 5. 数据完整性 ✅

- **外键约束**: 有绑定的资源无法删除（RESTRICT）
- **作用域检查**: 环境资源只能在其环境内使用
- **类型验证**: 属性定义与后端严格同步
- **唯一性**: 资源名称在作用域内唯一

### 6. 用户体验 💡

- **动态表单**: 根据资源类型自动生成表单
- **智能默认值**: 父资源、端口等自动填充
- **实时验证**: 表单提交前验证
- **权限适配**: 按用户权限显示/隐藏操作

## 数据流

### 1. 资源创建流程

```
用户填写表单
  ↓
前端验证（必填、类型）
  ↓
POST /api/resources
  ↓
后端验证属性（resource_types.validate_attributes）
  ↓
加密敏感信息（SecretBox）
  ↓
计算校验和（resource_types.checksum）
  ↓
插入数据库（resources + resource_versions）
  ↓
返回资源 ID
  ↓
跳转到资源详情页
```

### 2. 服务绑定资源流程

```
用户选择资源 + 输入别名
  ↓
POST /api/services/{id}/bindings
  ↓
验证资源存在且可访问
  ↓
验证别名唯一性
  ↓
插入 service_resource_bindings
  ↓
返回成功
  ↓
刷新绑定列表
```

### 3. 资源导出流程

```
服务发布
  ↓
resolve_config() 加载服务配置
  ↓
查询服务的资源绑定
  ↓
遍历每个绑定：
  - 获取资源当前版本
  - 解密属性
  - 计算导出（compute_exports）
  - 处理父子资源继承
  - 添加别名前缀
  ↓
合并到环境变量
  ↓
生成 Deployment YAML
  ↓
应用到 Kubernetes
```

### 4. 应用预置流程

```
用户选择预置 + 填写参数
  ↓
POST /api/environments/{id}/apply-preset
  ↓
验证必需资源类型存在
  ↓
验证必需参数完整
  ↓
更新环境 profile（merge profile_template）
  ↓
创建默认配置集（default_config_sets）
  ↓
返回成功
  ↓
刷新环境详情
```

## 已知限制

1. **资源类型扩展**: 需要同时修改后端和前端代码
2. **父子资源层级**: 当前支持 3 层，需要更深层级需扩展
3. **批量操作**: 暂不支持批量导入/导出资源
4. **资源使用追踪**: 未实现资源被哪些服务使用的反向查询
5. **预置版本管理**: 预置本身没有版本控制
